# Wio Lite AI RC 攀爬车装饰 UI 设计

## 1. 目标

基于 Wio Lite AI（STM32H725AEI6）开发套件制作 RC 攀爬车车壳装饰 UI。系统通过独立 UART 从运行 INAV 的飞控读取 MSP 数据，驱动 320×240 横屏彩色 UI 和 10～30 颗 WS2812 灯珠。

产品按以下顺序交付：

1. A：硬派越野仪表。
2. B：机械表情页面。
3. C：动态车身信息牌。
4. D：整合 A/B/C，通过遥控器 AUX、实体按键和可选触摸切换。

UI 板只负责显示与装饰，不参与舵机、电调、解锁或其他车辆控制。UI 板断电、复位或通信异常不得影响 INAV 控车。

## 2. 工程与硬件基线

- 原始工程：`E:\workspace\stm32\wio_lite_ai\wio_lite_ai`。
- 开发副本：`E:\workspace\fpv\wio_lite_ai_rc_ui`。
- 原始工程保持只读；所有设计文档、代码修改和构建产物只能进入开发副本。
- 副本保留原工程 Git 历史和用户对 `Core/Src/main.c` 的未提交修改。
- 显示屏：240×320 物理面板，LTDC、RGB565；产品逻辑坐标为 320×240 横屏。
- 摄像头：OV2640，当前版本不初始化 DCMI、摄像头或 AI 模型，仅保留现有源码与硬件接口。
- 外部 PSRAM：APS6408。
- UI 目标刷新率：稳定 30 FPS。
- 触摸屏硬件存在，但现有工程没有触摸控制器驱动；触摸属于可选增强，不得成为基本操作的依赖。

## 3. 技术路线

采用 LVGL 加裸机非阻塞事件调度，不在第一版引入 FreeRTOS。保留现有 STM32 HAL、BSP、LTDC 和 OSPI 初始化，主循环依次推进短时、非阻塞任务：

```text
MSP 收发 -> VehicleState 更新 -> 输入处理 -> 页面状态机
         -> LVGL 刷新 -> WS2812 更新 -> 诊断与看门狗
```

任何任务不得使用长时间阻塞等待。架构保持模块化，以便未来加入摄像头、Wi-Fi、音频或迁移至 FreeRTOS。

## 4. 系统模块

### 4.1 board_port

封装时钟、LTDC、OSPI PSRAM、UART、DMA2D、按键、定时器、缓存维护和看门狗。CubeMX 生成区与用户代码区必须区分，禁止直接覆盖用户的 `main.c` 修改。

### 4.2 msp_client

实现 MSP 客户端帧编码、解析、校验、请求调度、超时和统计。连接建立后先查询 API、固件标识和版本；基础数据优先使用兼容面较广的 MSP v1 公共查询，只有确认飞控能力后才启用所需的 INAV MSP2 查询。仅允许发送只读查询，禁止发送 RC Override、配置写入、解锁或控制命令。

初始轮询计划：

- `MSP_RC`：25 Hz。
- `MSP_ATTITUDE`：20 Hz。
- 电池/模拟量：5 Hz。
- GPS：5 Hz。
- 飞控状态：2 Hz。

采用单请求在途机制：收到响应或请求超时后才发送下一条请求。UART 使用 INAV 空闲全双工端口，115200 baud、3.3V、非反相、TX/RX 交叉连接并共地。

### 4.3 vehicle_state

作为 UI 和灯效的唯一车辆数据来源，包含：

- 油门、转向和 AUX 通道。
- 横滚角、俯仰角和航向。
- 电池电压、电流、容量和低电状态。
- GPS 可用性、速度、卫星数等可用字段。
- 解锁状态、飞行模式和传感器状态。
- MSP 链路状态、数据时间戳和故障标志。

本模块负责通道归一化、死区、低通滤波、范围校验、数据陈旧判断和告警优先级。页面不得直接读取 UART 缓冲区。

### 4.4 ui_port 与 ui_app

`ui_port` 提供 LVGL 时基、RGB565 刷新、320×240 横屏映射、DMA2D 和缓存一致性处理。`ui_app` 提供公共状态栏、页面状态机、主题和 150～250 ms 机械遮板/警示条转场。

### 4.5 页面模块

- `screen_dashboard`：油门和方向为视觉中心，常显电池、姿态、GPS、解锁和链路状态。
- `screen_face`：机械护目镜式眼睛；油门控制眼睛张力，转向控制视线，倒车、低电和失联使用专用表情。
- `screen_showcase`：循环显示车名、Logo、越野标语和警示纹理；油门、转向和解锁状态驱动场景变化。

三页统一使用深色金属底、警示黄、高对比字体、粗线条和工业警示纹理。

### 4.6 input_manager

- AUX 三段开关固定映射 A、B、C，是最高优先级页面输入。
- 实体按键短按循环页面，长按进入亮度设置。
- AUX 位置变化时立即覆盖本地页面选择。
- 触摸控制器识别并验证成功后，允许点击切页和亮度滑动；触摸不可用时隐藏功能且不报致命错误。

### 4.7 led_controller

支持最多 30 颗 WS2812，逻辑分为左侧、右侧和全车区域：

- 待机：低亮暖黄色呼吸。
- 前进：亮度随油门平滑变化。
- 转向：对应侧黄色流水。
- 倒车：两侧低亮白色脉冲。
- 解锁：启动扫描后进入当前页面灯效。
- 低电：黄色三连闪，每 5 秒重复。
- MSP 失联：低频黄色双闪。
- 本板故障：红色短闪故障码，禁止持续高亮。

优先级为：本板严重故障 > MSP 失联 > 低电压 > 转向/倒车 > 页面装饰灯效。

### 4.8 diagnostics

记录帧率、最长主循环时间、MSP 请求/超时/校验错误计数、状态年龄、复位原因和 LED 估算电流。启动失败时提供屏幕故障页或 LED 故障码。

## 5. MSP 失联与恢复

- 单次请求超时：放弃响应，继续调度，不阻塞 UI。
- 连续 500 ms 无有效 MSP：标记数据陈旧，冻结快速变化的仪表值。
- 连续 2 s 无有效 MSP：进入失联页面与黄色双闪。
- MSP 恢复且持续稳定 500 ms：自动退出失联状态。
- 长度、范围或校验不合法：丢弃整帧，不进行部分状态更新。

## 6. 显示与内存

320×240 RGB565 单帧为 153,600 字节。优先评估双缓冲；如 PSRAM 带宽或缓存维护不满足目标，则使用 LVGL 分块绘制缓冲。DMA2D 用于填充、拷贝和像素格式相关加速。

显示旋转封装在 `ui_port`，所有业务页面只使用 320×240 坐标。摄像头缓冲和 AI 推理内存在当前模式不分配。

## 7. 供电与电气约束

- 动力电池通过新增独立 5V 降压模块供电，持续能力至少 3A。
- Wio 与灯带分支供电并共地，入口分别去耦。
- WS2812 数据使用 3.3V 到 5V 电平转换，并串联 220～470Ω 电阻。
- 按 30 颗全白极限约 1.8A 预留硬件能力。
- 固件默认使用 1A 电流预算，根据颜色和亮度估算总电流并限制全局亮度。
- 上电时灯带保持关闭，UI 和基础诊断就绪后再渐亮。

## 8. 明确不在第一版实现

- 摄像头画面、AI 推理和障碍识别。
- Wi-Fi、BLE、MicroSD 主题上传或在线编辑。
- 音效。
- MSP DisplayPort 字符 OSD。
- Wio 对车辆的任何控制输出。
- 依赖未验证触摸控制器的必要交互。

## 9. 实施顺序

1. 横屏 LVGL 基础、缓存策略和诊断页面。
2. MSP 客户端与主机侧模拟数据测试。
3. A 越野仪表。
4. B 机械表情。
5. C 动态信息牌。
6. D 页面状态机、AUX 和实体按键。
7. WS2812 灯效、优先级和电流限制。
8. 识别并验证触摸控制器；验证失败时维持可选状态。
9. 整车电源、干扰和长时间运行测试。

## 10. 验收标准

- 320×240 横屏稳定显示，目标 30 FPS。
- 连续运行 4 小时无死机、花屏或不可恢复卡顿。
- MSP 正常时，RC/姿态到视觉变化的延迟不超过 100 ms。
- 断开 MSP 后 2 秒内进入失联状态，恢复稳定 500 ms 后自动退出。
- AUX 可靠选择 A/B/C；实体按键在 AUX 未变化时可以备用切换。
- 30 颗灯珠工作时不导致 Wio 复位，软件电流限制有效。
- 触摸不存在或初始化失败不影响 AUX、按键和页面显示。
- UI 板断电、复位或串口异常不影响 INAV 控车。
- 原始工程除用户已有的 `Core/Src/main.c` 修改外不产生任何新文件或变更。
